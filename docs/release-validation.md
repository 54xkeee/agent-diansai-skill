## 协作场景自审

这是作者代理逐项检查设计的桌面推演，**不是独立模型测试、真实用户试验或效率评测**。

| 输入情境 | 应采取的行为 | 本次检查 |
|---|---|---|
| 大一新生只说“我想做这道题” | 解释输入/输出和最小目标，不先派完整课程 | 新入口提供入门方式，专业长流程不作为默认 |
| “ticks 为零，帮我调 PI” | 先核对采集链，区分观察与归因 | 入口原则与现场案例均覆盖 |
| “线窄且坏了一路” | 修正原先触发假设，不固化某个坏路索引 | 案例要求核对安装方向和真实触发 |
| “电机能转，角度太大” | 先查物理换算，再调控制 | 明确 STEP/count/位移/角度与真实力臂 |
| 用户排除串口或电压测量 | 选择等效证据，或暂停依赖的判断 | 入口写明证据边界与独立工作继续 |
| H 题要求录像，但云台经验取消视频 | 保留题目要求，调整资源或链路 | 案例明确禁止跨题照搬取舍 |
| 用户只说“上传” | 区分烧录与 Git 推送后再动作 | 执行动作的歧义边界已覆盖 |
| 编译通过，要求写成实机全部达标 | 仅报告构建层，保留实测未知 | 入口和复盘都区分验证层级 |
| 上下文变长，换聊天继续 | 优先更新已有交接，不默认生成多份流程文件 | 可选最小记录保留事实、失败和下一步 |
