# 协作情境回放：检查下一步是否真正改变

这不是用关键词匹配skill，也不是一次独立模型A/B测试。以下由本次编写代理根据历史案例重构输入，再作决策推演，含已知后果，存在事后知识偏差。用途是审查规则有没有具体行动含义、是否过度概括，并留下可用于后续盲测的情境；不据此给出效果提升百分比。

## 针对过度约束的反查

- 最小实验不是永远禁止架构调整：真实瓶颈在共享调度时，允许完整修改必要依赖。
- 保存成功经验不是保留错误常量：物理关系变化时应换算，保护的是行为和目标。
- 尊重现场不等于自动接受归因：人对现象有直接信息，AI仍要检验其解释；AI也会误读图片与代码。
- 重视证据不等于把所有工作交给人：能从工程定位的映射、状态和输出关系应由AI完成。
- 停止盲改不等于停止工作：先对比版本、增加最小有效观测、缩小分歧，独立工作继续。

## 本次能支持什么

已逐项作出明确决策，检查新版入口与案例是否能支撑这些区别，并检查反例是否仍允许合理调参、成组修复与技术决断。这个结果支持设计的可解释性，不支持“新模型已经学会”“真实新生完成率提升”或“18/18模型测试通过”。

后续若做独立测试，应只给评估者skill、情境输入和必要工程片段，隐藏右两列及历史后果；记录实际读取、修改、索取证据与最终判断。不要只检查回答是否出现“最小实验”“人机协作”等词。
