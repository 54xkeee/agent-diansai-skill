# 电赛机电系统风险检查表

仅把本检查表用于发现候选风险。不要机械地把每一项都写进报告；保留与当前赛题有明确因果关系的内容。

## 感知与标定

- 传感器测到的是目标状态，还是目标状态的间接代理量？
- 静态标定能否覆盖运动中的误差？
- 零偏、比例误差、安装误差、积分漂移和温漂分别会影响什么？
- 关键动作期间是否会遮挡、饱和、失焦、丢线或超出量程？
- 采样率、延迟和滤波相位滞后是否会破坏闭环？
- 器件批次、兼容型号、I2C 地址或初始化行为是否可能不同？
- 能否交叉验证关键状态，或检测传感器已经失效？

## 执行器与控制

- 电机、舵机、云台或功率器件是否存在死区、饱和、迟滞、间隙和最小动作量？
- 控制对象在启动、制动、换向、转弯和负载变化时是否显著改变？
- 控制量突变是否导致电流、振动或姿态突变？
- 闭环使用的观测量是否在关键动作期间仍然可信？
- 执行器达到极限后，积分项或状态机是否仍继续累积错误？
- 是否需要先粗定位，再使用另一种观测完成精定位？

## 供电、接地与通信

- 启动、堵转、发射、无线发射或负载切换时的峰值电流是多少量级？
- 电机与逻辑电源是否相互影响？地回流路径是否会污染传感器参考地？
- 压降、纹波、反电动势和 EMI 会造成复位、通信异常还是测量漂移？
- I2C、SPI、UART 或 CAN 的错误是否能被检测和恢复？
- 通信失败时控制逻辑会继续使用旧数据、错误数据还是进入安全状态？
- 接插件、线长、上拉、终端和布局是否适合现场机械振动与噪声环境？

## 机械与动态过程

- 重心、轮距、轮胎、刚度、摩擦和负载变化如何改变运动模型？
- 安装角误差、结构形变和重复装配误差是否会破坏标定？
- 转弯、急停、发射或云台动作是否造成相互扰动？
- 稳态测试中看不到的问题，是否会在状态切换瞬间出现？
- 完成动作后需要等待稳定、主动抑振，还是边运动边完成下一任务？
- 机械能力不足时，软件是否被迫补偿一个不可观测或不可控的问题？

## 实时性与软件状态

- 每个控制环、采样任务和通信任务需要多高频率？
- 阻塞调用、日志、显示、Flash 写入或总线错误是否会拖慢关键控制环？
- 状态切换是否有去抖、超时、滞回和异常出口？
- 系统能否记录足够数据来区分根因，而不会显著扰动实时性？
- 看门狗复位是否会隐藏问题，还是能把系统恢复到可继续比赛的状态？
- 故障后能否局部重初始化传感器或通信，而不重启整个任务？

## 环境与比赛流程

- 实验室条件与现场在光照、地面、背景、温度、供电和干扰方面有何不同？
- 裁判摆放误差、起始位置误差和人工操作差异是否会累积？
- 单次表现好是否只是偶然？需要多少次重复实验才能判断稳定性？
- 调试时可用的外部仪器、时间和操作，在正式比赛时是否仍可用？
- 有哪些简单降级策略可以保住基础得分？

## 反向检查

对每个技术路线追问：

1. 它依赖哪些尚未验证的物理假设？
2. 哪个单点失败会同时摧毁多个得分项？
3. 最便宜的否定实验是什么？
4. 测试失败时，是否有更简单的保底路线？
